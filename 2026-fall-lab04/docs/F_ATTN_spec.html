A3輸入的時序與順序Input timing & raster order

每個 cycle 每條線只進來一個 FP32

Q、K、V、out_weight 各只有一條 32-bit 的線，一拍只送一個數 (一個維度)，一個 token 的 4 維要 4 拍才送完。Q、K、V 三條線同一拍各送一個數，而且是同一個 token 的同一維，例如 cycle 5 會同時收到 Q、K、V 的 token 1 dim 1 (從 0 數)。out_weight 也同時開始，但只有前 16 拍有效。

Raster order = row-major。第 c 拍 (從 0 數) 送進來的是 token = c / 4、dim = c % 4。dim 0、1 屬於 Head 1，dim 2、3 屬於 Head 2。格子裡的數字是它在第幾拍進來：

Q / K / V (16×4)，Head 1 Head 2
out_weight W (4×4)，前 16 拍

外層 loop：Q_block i = 0..7 ・ 內層 loop：K_block j = 0..7。

A6浮點格式IEEE-754 FP32

32 bit = 1 bit sign + 8 bit exponent (bias 127) + 23 bit fraction，值 = (−1)s × 1.f × 2e−127。以 TA 給的 √2 常數為例：

sqare_root_2 = 32'h3FB504F3 ・ sign + ・ exponent 127 − 127 = 0 ・ value ≈ 1.4142135

parameter 名稱是 TA 拼的 sqare_root_2 (少了 u)。spec 強調「Please follow the parameter TA set」。

Infinity (spec 特別提醒)

|Q| ≤ 0.5、|K| ≤ 255，|S| 最大約 2 × 0.5 × 255 / √2 ≈ 180。float32 的 ex 在 x > 88.7 就溢位。所以一定要先減 running max，讓指數 ≤ 0；eS−m 很小時 underflow 成 0 沒關係。

誤差只允許 1e-7 (絕對值)

輸出量級大約 0.1 ~ 1，float32 在 0.5 附近的 1 ulp ≈ 6e-8，等於只容許差 1 ~ 2 個 ulp。運算順序都可能影響是否過關 (見 B9)。

B2設計方向的推導Why this shape

整個架構是從評分公式和 latency 的定義推出來的。這一節講清楚推導過程，後面每個細節都建立在這裡的結論上。

1. 評分公式：Area² × Latency × T

面積是平方，影響比 latency 和 T 大：面積減半，分數變 1/4；latency 減半，分數只變 1/2。所以一開始的直覺是「少放硬體、多花幾拍」。但下面第 2 點會推翻這個直覺。

2. latency 只算到「第一個」out_valid

spec 第 6 條：latency 從 in_valid 下降緣算到第一個 out_valid 上升緣。輸出的 64 拍不算在 latency 裡。所以如果第一個 Final 一算好就開始輸出、其他的邊算邊送，大部分計算可以藏進輸出的那 64 拍。

做法latency
全部算完再輸出整個計算時間 (一拍一 tile 也要 70 拍以上)
邊算邊送只到第一個 Final 算好，約 8 拍

3. 邊算邊送要求「產生速度 = 輸出速度」

out_valid 必須連續 64 拍，每拍要有一個 Final 可以送。一個 Q_block (2 個 token) 會產生 2 × 4 = 8 個 Final，所以一個 Q_block 必須在 8 拍內做完，也就是一拍一個 tile。兩個 head 都要在同一個 Q_block 完成，Final 才能算 (Final 需要兩個 head 的值)，所以兩個 head 並行。

4. 快但大，還是慢但小？

設 F = 儲存等固定面積、U = 一拍一 tile 需要的運算面積、r = 產生速度 (每拍幾個 Final)。速度 r < 1 時輸出要晚開始，latency ≈ 8 + 64 × (1/r − 1)：

r面積latency分數比較 (相對 r = 1)
1F + U≈ 8基準
0.5F + U/2≈ 72r = 1 的分數 / r = 0.5 的分數 ≤ (1/9) × 4 ≈ 0.44，r = 1 較好
0.25F + U/4≈ 200≤ 8 × 16 / 200 = 0.64，r = 1 較好
結論與前提

在這個模型下，不管 F、U 是多少，一拍一 tile 都比較好，因為省下的面積最多一半，latency 卻多好幾倍。前提是兩種架構的 T 一樣，而且一拍一 tile 的面積要塞得進上限 4,000,000 (12 顆 exp、10 顆除法器…)，這要等 DW 單元的實際數字確認。

5. DesignWare FP 單元是純組合電路

查證 Synopsys 文件：DW_fp_mult 等標準 FP 單元只有 a、b、rnd、z、status，沒有 clk。只要 T 夠長，一拍就算完。所以：

  • 單元的 delay 直接決定 T。最慢的 exp、div 要盡量自己一級，或自己插 register 切開。
  • 要多拍的變體要另外選：DW_fp_div_seq (循序除法器，num_cyc 拍算完，面積較小)、DW_lp_piped_fp_* (minPower 系列，要確認 license)。

6. 為什麼不用 systolic array

  • Area² 很貴：systolic array 是多放 PE 換速度，大部分 PE 會在等資料。
  • 矩陣太小：head_dim = 2，每個 score 只是 2 項內積，一顆 DW_fp_dp2 就做完，沒有長的累加鏈可以利用。
  • 瓶頸不在矩陣乘法：exp 和 online softmax 的序列相依 (先 max 才能 exp) 是 systolic array 處理不了的。

資料word為什麼一定要存

數量省不了，能省的是「怎麼存」。

2. 用 shift 取代隨機讀取

如果 buffer 可以隨機讀，每個讀取埠都要一顆 64 選 1 × 32 bit 的 mux，面積可能跟 FF 本身差不多。這題的讀取順序完全固定：每個 Q_block 都依序讀 K_block 0 → 7，讀完回到 0。所以用 shift / ring，資料自己移到固定的讀取位置，讀取端不需要 mux；寫入也是照順序 shift in，不需要寫入 decoder。

3. Lane：一個 column = 一個 head 的 2×2 block

每個 head 的資料拆成 4 條 lane × 8 格，每格 1 個 FP32。4 條 lane 對應 block 內的 4 個位置，同一個 column 的 4 格就是一個 2×2 block (2 token × 該 head 的 2 維)。

// Head 1 的 block b
             dim0      dim1
token 2b   [ lane 0 ][ lane 1 ]
token 2b+1 [ lane 2 ][ lane 3 ]
// Head 2 的 block b
             dim2      dim3
token 2b   [ lane 0 ][ lane 1 ]
token 2b+1 [ lane 2 ][ lane 3 ]
為什麼拆成 4 條 lane，不用一條 32 格的 ring

一條 32 格的 ring：輸入時一次移 1 格，轉一個 block 卻要一次移 4 格，每個 FF 前面要 3 選 1 mux (保持 / 前 1 格 / 前 4 格)，K、V 共 4096 個 FF 都要多這顆 mux。拆成 4 條 lane 後，轉一個 block = 4 條 lane 同時移 1 格，輸入一個 word = 對應的那條 lane 移 1 格，兩種操作都是「從前 1 格來」，每個 FF 只要 2 選 1。這等於一條 8 格、每格 128 bit 的 ring，只是把寬度拆成 4 條 32 bit，讓輸入時可以一條一條填。

例外：如果 datapath 一拍只吃 1 個 word、4 拍吃完一個 tile，一條 32 格每拍移 1 格的 ring 就夠了。我們是一拍吃一整個 tile，所以用 lane。

4. Head Switcher：1 對 8 的寫入 enable

第 c 拍 (c = 0 ~ 63) 的 word 寫到哪條 lane 只看 c[2:0]。Q、K、V 同一拍、同一個位置進來，三者共用同一組 enable。它不是 data mux，資料線直接接到所有 lane，只有 enable 不同。

c[1] 決定 head、c[2] 決定 block 內的偶 / 奇 token、c[0] 決定 head 內的哪一維。c[5:3] (第幾個 block) 不用解碼：每條 lane 每 8 拍收到一個 word，64 拍後剛好各收 8 個，自動對齊，block 0 在頭端。

互動：K buffer 怎麼填、怎麼轉

格子標 ttokend維度 (從 0 數)。左邊框起來的是頭端 (讀取端)，右邊是尾端 (新資料進來)。拉「輸入 cycle」看每條 lane 每 8 拍收一個 word；輸入完成後拉「tile j」看整個 column 往左轉、最左邊繞回尾端。V 和 K 完全同步。

5. K、V：ring，每個 tile 轉一格

  • 每做完一個 tile，同一個 head 的 4 條 lane 一起移一格，最左的 column 繞回尾端。下一個 K_block 就到頭端了。
  • 轉滿 8 次剛好回到原位，不需要回填或重設，下一個 Q_block 直接從 block 0 開始。
  • V 跟 K 同步轉，因為 tile j 的 score 要乘的就是 V_block j。

6. K/V 的 head/tail mux：為什麼輸入期間讀尾端

lane 是從尾端填的：新 word 從 entry 7 進來，往 entry 0 推。block 0 要等整條 lane 收滿 8 個 (輸入結束) 才會到頭端。在那之前，剛到齊的 block j 一定在尾端。

為什麼值得

在 block 剛到齊時就從尾端拿去算，Q_block 0 跟著輸入同步完成，latency 從約 15 拍降到約 8 拍。分數直接乘上 latency，等於差將近 2 倍。代價只是 K、V 讀取端各一個 column 的 2 選 1 mux。

7. Q：current 暫存器 + 7 格 lane，不寫回

  • Q_block 0 要在輸入期間就用，但它在 lane 裡會一路移動，沒有固定位置可讀。所以第 0 ~ 7 拍進來的 Q_block 0 直接存進 current 暫存器，Q_block 1 ~ 7 存進 7 格深的 lane。總容量一樣 8 個 block。
  • 每個 Q_block (8 個 tile) 做完：current ← lane 頭端，lane 移一格。K/V 轉滿一圈剛好對應 Q 走一格。
  • Q 寫入用同一組 Head Switcher enable，只是 c[5:3] = 0 時寫 current，其他寫 lane。
  • 不寫回 Head_out：因為邊算邊送，Head_out 幾拍內就被 dp4 用掉，放在小的 H 暫存器就好 (見 B6)。早期版本是把 Head_out 寫回 Q 的尾端，邊算邊送之後就不需要了。

8. W：4 lane × 4 的 ring

  • W 作用在兩個 head 拼起來的 4 維上，不分 head。
  • 4 條 lane (k0 ~ k3) × 4 格 (row 0 ~ 3)。第 c 拍進來的是 W[c/4][c%4]，用 c[1:0] 選 lane，只在 c < 16 時寫入 (之後 out_weight 是 X)。16 拍後自動對齊。
  • 輸出順序是 Final[t][0..3]，每拍要換下一列 W，0 → 1 → 2 → 3 → 0 循環，剛好是 ring。讀取端 column 就是 W 的一整列，直接接 dp4。

9. Exponent 壓縮

exponent 數量取決於範圍跨了幾個 2 倍 (dynamic range)，不是上限多大：

訊號範圍可能的 exponent壓縮還原省
Q、V、W±0 ~ 0.50 ~ 126拿掉 bit 30 (|x| < 1 時一定是 0)bit 30 補 0，只是接線144 bit
K±0.5 ~ 255126 ~ 134 (9 種)只存 exponent 低 4 bit{~b3, b3, b3, b3, b[3:0]}256 bit
  • Q/V/W 只能省 1 bit：下限是 0，0.5、0.25、0.125 … 可以一直減半 126 次，比例是無限大倍。PATTERN 均勻亂數時小 exponent 很少出現，但「很少」不等於「不會」，不能靠機率壓 bit。
  • K 能省 4 bit：0.5 到 255 只跨 9 個 2 倍。126 ~ 134 的低 4 bit (1110、1111、0000 ~ 0110) 都不一樣，高 4 bit 由 b3 決定 (b3 = 1 → 0111，b3 = 0 → 1000)，還原只要一顆 inverter 加接線，不用加法器。
  • 合計約 400 bit，約 6%。
K 的壓縮要等助教確認範圍

只要 K 出現 0、小於 0.5 或大於 255，結果就錯。建議先做 Q/V/W 的 1 bit，K 等確認後再加。PATTERN 要測 0.5、255、0、負號等邊界值。另外 Final 最大可到 4 × 0.5 × 0.5 = 1.0，exponent 會變成 127，不能用這種格式存；目前 Final 不存，所以沒問題。

10. 資料暫存器的 reset

資料暫存器 (buffer、pipeline register、快照、H) 不接 reset 可以省面積，只有 out_valid、out、FSM、counter 需要 async reset。這點暫時不考慮，之後優化面積時再處理。

2. D 和 M 在算什麼

列 a 最後要得到所有 16 個 V 的加權平均，score 越高權重越大：

          Σ e^(s_k − Max) · V_k[d]        ← 分子 M

          Σ e^(s_k − Max)                 ← 分母 D
        (k = 0 ~ 15)

D、M 是「到目前為止處理過的 token」的累加值。每個 tile 加 2 個 token，8 個 tile 加滿 16 個。權重是以 Max 為基準算的，Max 變大時，舊的累加值要乘 C 換到新基準：e^(s − Max_old) × e^(Max_old − Max_new) = e^(s − Max_new)。分母要等 16 個都加完才知道，所以分子分母各自累加，最後才除一次。

3. 狀態暫存器

3. 要跟著 tile 往後傳的資料

  • Max_old、Max_new：S3 算 Ca 時，S2 的 Max 暫存器已經被下一個 tile 改掉了，所以 S2 要把減完的結果 (S − Max'、Max − Max') 存進 pipeline register 往後送。
  • V：V 在 S1 跟 K 一起讀出，S4 才用到，要往後傳 3 級 (每個 head 12 word)。也可以讓 V ring 比 K 晚 3 拍轉來省掉，但 Q_block 0 在輸入期間各 lane 的讀取位置會不一樣，很亂，目前不採用。

如果 S4 的 mult + add 太慢、必須拆成兩級來降低 T，回授就跨 2 拍：tile 1 要用 tile 0 的 M 時，tile 0 還沒算完。這時同一個 Q_block 的 tile 不能連續送，要交錯獨立的資料來填空檔，例如列 a、列 b 交錯，或兩個 head 交錯。回授跨幾拍，就要交錯幾組。這會改變整個時間表，所以要等量出 delay 再決定。

B6輸出路徑Snapshot → divider → H → dp4 → out

輸出路徑的工作是把「每 8 拍一次、一次 6 個值」的 D、M，轉成「每拍一個 Final」。所以快照和 H 暫存器雖然也是 stage 之間的 register，但跟 S1 ~ S4 之間的不一樣：

S1 ~ S4 之間D/M 快照H 暫存器
寫入每拍每 8 拍一次每拍寫 1 個
保持1 拍4 拍最多 8 拍
enable不需要 (可用 valid bit)需要需要
讀取整組接下一級每拍讀不同的值前 4 拍 token a、後 4 拍 token b

1. D/M 快照：為什麼需要

Q_block i 的最後一個 tile 在 S4 更新完後，D、M 是最終值；但下一拍，Q_block i+1 的 tile 0 就會在 S4 覆蓋它們。最終值只存在 1 拍，所以要在那一拍把 6 個值 (M × 4、D × 2) 複製出來。

2. 快照用 shift 結構

M shift：[ Ma0 | Ma1 | Mb0 | Mb1 ]   每拍往左 shift 一格，除法器讀最左格
D shift：[ Da  | Db  ]                每 2 拍 shift 一次，除法器讀左格
為什麼用 shift：省的是 timing，不是面積

快照要一次載入 6 個值，所以 shift 的每一格也要選「載入 / shift」，跟讀取 mux 的面積差不多 (都約 4 顆 32-bit 2 選 1)。真正的好處是：除法器是很長的組合電路，很可能決定 T；用讀取 mux 的話 mux delay 加在除法路徑上，用 shift 的話 mux 在快照暫存器的輸入端，除法器輸入直接接暫存器，關鍵路徑上沒有 mux。這也跟整個設計「只讀固定位置」的風格一致。

3. 除法器：每個 head 一顆，分時做 4 次

DW_fp_div 是組合電路，每筆一拍就算完。一顆除法器輪流做 4 次除法 (time-multiplexing，不是 pipeline)，每 8 拍有 4 拍閒置。

4. H 暫存器與 dp4：為什麼一次讀一個 token 的兩個 head

Final[t][k] = H[t] · W[k]：H 的一列 (一個 token，兩個 head 共 4 個值) 和 W 的一列做內積。spec 要求 raster 順序 (先固定 token、再跑 4 維)，所以 H 固定一列連續用 4 拍，W 每拍轉一列：

拍dp4 讀的 H (兩個 head 都讀)W輸出
1 ~ 4H1a0 H1a1 H2a0 H2a1W[0] ~ W[3]Fa0 ~ Fa3
5 ~ 8H1b0 H1b1 H2b0 H2b1W[0] ~ W[3]Fb0 ~ Fb3
 
Fa[k] = H1a0·W[k][0] + H1a1·W[k][1] + H2a0·W[k][2] + H2a1·W[k][3]
        └────── Head 1 ──────┘         └────── Head 2 ──────┘
  • H 和 W 都以「列」為單位存、以「列」為單位讀，跟矩陣乘法的方向對齊，不用轉置。
  • H 在 4 拍內完全不動，只在換 token 時切一次 a/b 2 選 1 mux；W ring 每拍轉一格。
  • 如果反過來固定 W、每拍換 token，順序會變成 Final[0][0]、Final[1][0] …，不符合 raster，還要多一塊 buffer 重新排序。
  • H 用 shift 寫入：除法器依序產生 Ha0、Ha1、Hb0、Hb1，從同一端推入，不用寫入 decoder。

5. out 暫存器

dp4 的結果打一拍進 out 暫存器再輸出。out_valid 為 0 時 out 必須是 0 (spec)，reset 後兩者都要是 0。
