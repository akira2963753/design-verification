# LDPC Lab02 — DC Sweep 與優化結果

- 更新: 2026-09-24
- 原始數據: `05_SWEEP/results.json` (腳本自動報表: `05_SWEEP/DC_SWEEP.md`)
- 產生工具: `05_SWEEP/dc_sweep.py` (VCS + DC 自動化, 見第 11 節)

## 1. 結論

- 目前最佳: **v16a @ 3.2 ns**, Area **187,321 µm²**, Latency **4340** (avg 21.7), Cost **4.873E+14** (total latency) / **2.437E+12** (avg latency)
- 相對 v2 最佳 (4.5 ns) **-32.1%**, 相對 v1 (8.0 ns) **-67.1%**
- 相對 v4 (重構基準, 最佳 4.0 ns) **-19.1%**
- 所有版本 VCS RTL 200/200 pass, 有效點皆 0 latch / 0 error

## 2. 量測條件

| 項目 | 設定 |
|---|---|
| Cost | Area² × Cycle × Latency |
| Latency (total) | PATTERN 印出的 total latency, 200 筆加總 |
| Latency (avg) | total / 200; 兩種 cost 只差固定倍數, 排序相同 |
| RTL 模擬 | VCS 2021.09, `make vcs_rtl`, TA 200 筆 (約 16 s) + 自產 1000 筆 regression |
| 合成 | dc_shell 2018.06, `02_SYN/syn.tcl` 只改 `CYCLE` |
| Library | server 的 90 nm library (非 NYCU UMC018), 面積不能和 NYCU 環境直接比 |
| Clock | spec: clock 精度 0.1 ns; v4 之後以 0.2 ns 為主 (3.2~4.6 ns), 最佳點附近補 0.1 ns; 3.0 ns 一律違規, 5 ns 以上一律較差 |
| 有效點 | VCS pass, slack MET, 0 error, 0 latch, 單筆 latency ≤ 100 |

## 7. Critical path

v14 之前的最佳版本 v9 @ 3.6 ns (`work/v9/syn_T3.6/Report/LDPC.timing`), 最差 path slack 0.00 (v14 @ 3.6 ns 的最差 path 改為 `a_q` → `a_q`, arrival 同為 3.42 ns):
- Startpoint `h_q[668]` (CNU 15, port 6 的 -C2V_old) → Endpoint `a_q[534]` (A bank group 4, slot 2), arrival **3.42 ns** = 3.60 - uncertainty 0.10 - setup 0.08
- DC 會把 timing 預算用滿 (arrival = required), 多出來的時間都拿去縮小面積

| 區段 | v9 @ 3.6 ns | v3d @ 4.0 ns | 差異原因 |
|---|---|---|---|
| head clk→Q | 0.22 | 0.15 | 起點改用一般 FF (DFFQX2) |
| `ta = A - C2V_old` adder | 0.41 | 0.56 | head 預先存 -C2V_old, 沒有條件反相 |
| V2C key → MIN4 / MIN3 → final merge | ~1.44 | ~1.64 | |
| normalize | ~0.52 | ~0.30 | 3.6 ns 下 DC 用不同結構 |
| 新 C2V magnitude 選擇 (one-hot) | 0.18 | ~0.25 | |
| `b_new` adder | 0.42 | 0.64 | |
| 寫回 rotation mux → `b_d` | 0.14 | 0.12 | |
| A mux → `a_d` | 0.09 | 0.18 | Toeplitz 擺放, A 的 move mux 多為 2:1 |
| **合計** | **3.42** | **3.84** | |

## 8. 觀察

1. Latency 已到下限 (4 × iter, total 4340), cost 只能靠 Area² × Cycle 下降
2. timing 帶來的面積幾乎都在 CNU: 單獨合成一顆 CNU (v4), `b_new` 預算 3.3 ns 為 6,875 µm², 8 ns 為 5,323 µm², 16 顆差 25k, 與整顆 design 4 ns / 8 ns 的差距 (22k) 相當
3. CNU 層級比較 (單獨合成, `b_new` 3.3 ns / `w_new` 3.6 ns), 比整顆 sweep 快且雜訊小:

| CNU | 單顆面積 (µm²) | vs v4 |
|---|---|---|
| v4 | 6,875 | - |
| v5 (normalize 提前) | 7,102 | +3.3% |
| v7 (v5 + one-hot idx + -C2V_old head) | 6,357 | -7.5% |
| **v7b** (v4 + one-hot idx + -C2V_old head) | **6,187** | **-10.0%** |
| v7c (v7b, ones' complement head) | 6,403 | -6.9% |
| v8 (rank-7, 21 comparators) | 6,625 | -3.6% |
| v9 (CNU 與 v7b 相同) | 6,187 | -10.0% |
| v14 (v9 + normalizer 63 項查表) | 6,060 | -11.8% |
| v14b (v9 + normalizer `3·key[5:3] + t`) | 6,038 | -12.2% |
| v15a (v14 + key 63) | 6,175 | -10.2% |
| v15b (v14 + final merge 前 normalize) | 5,934 | -13.7% |
| **v15** (v14 + key 63 + final merge 前 normalize) | **5,892** | **-14.3%** |

4. Toeplitz 擺放 (v9): BG[k][c] = BG[k-1][c-1], column 沿對角線滑動後 layer 0→1→2→3 的寫回來源完全相同, 只有 layer 3→0 要跳一次 (BG 不是 circulant); 寫回 mux 輸入 B 30 → 26, A 25 → 18, 合計 55 → 44 (annealing 多個 seed 都收斂在 44); 4.0 ns 面積 v7b → v9 **-7.2k**, 比 mux 數量的預估大, 因為寫回 mux 在 critical path 尾端
5. Normalizer (v14 / v14b): v9 的 `(3y + c) >> 2` 被 DC 做成 3 輸入 CSA + 7-bit CPA (resource report 的 DP_OP), 而且在 critical path 上; 改成查表或 `3·key[5:3] + t` 後 CNU -2.1% / -2.4%, 整顆 design v14 在 3.4~3.7 ns 每一點都比 v9 小 (3.4 ns -3.6%, 3.6 ns -1.4%), clock 越緊差越多; v14b 雖然 CNU 較小, 整顆 design 在 3.5 / 3.6 ns 反而比 v14 大約 2.4% (比 v9 大 0.6~1.0%), 採用 v14
6. FIFO 歸零只閘 magnitude (v14 / v14b): reset 後第一筆 pattern 的 FIFO idx / sgn 是 X, head 要是 0 得靠 decompress 把 X 擋掉; server netlist 3-valued 檢查 (`xcheck_head.py`) 672 個 head D pin 全為 0, 但其中約 440 個 MXI2 是靠 "select = X 且兩個資料輸入相等" 擋掉, 依 cell model (UDP) 而定, UMC018 需在 03_GATE 確認
7. Final merge 前 normalize (v15): 查表比 6-bit compare 快, 藏在 final compare 後面, CNU -2.1% (v15b); 整顆 design 最佳點從 3.6 ns 移到 3.3 ns, cost 比 v14 -7.7%; key 63 單獨做 CNU +1.9%, 配 v15b 是 -0.7%, 在雜訊內; v15r (輸出打一拍) 在 3.2 ns 面積與 v15 相同, output path 不是面積來源, 多 200 latency 反而較差
