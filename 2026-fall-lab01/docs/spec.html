Design Description and Examples

In today's high-performance computing era, processor performance depends not only on clock frequency but also on how efficiently independent instructions are scheduled. Since instructions may have different execution latencies and data dependencies, issuing every instruction strictly in program order can introduce unnecessary stalls and increase the total execution time.

In this lab, you will design an Out-of-Order Instruction Scheduling Solver (OISS). The solver receives eight instructions and their execution latencies, analyzes register dependencies, and determines a legal issue order with the minimum execution cycle count. Independent instructions may overlap in execution, while dependent instructions must preserve the required relationship.

Your design must output the minimum cycle count and one corresponding instruction order. If multiple optimal orders exist, any legal order achieving the same minimum cycle count will be accepted.

Description of Lab

➤ Input:

You will receive two input signals:

Inst_seq_I (96 bits):

contains eight 12-bit instructions. Instruction 0 is stored in the least significant 12 bits, and instruction 7 is stored in the most significant 12 bits.

Inst_latency_I (48 bits):

input contains the execution latency of the eight supported opcodes. Each opcode latency is represented by 6 bits, and the bit range is assigned according to the opcode order.

➤ Instruction Format

Each instruction is 12 bits and is divided into four 3-bit fields:

[11:9] opcode | [8:6] rs | [5:3] rt | [2:0] rd

Detailed instructions are shown below:

Function Name Meaning Instruction Binary Encode
ADD rd = rs + rt 000-rs-rt-rd
SUB rd = rs - rt 001-rs-rt-rd
MUL rd = rs * rt 010-rs-rt-rd
DIV rd = rs / rt 011-rs-rt-rd
Load rd = DM[\{2'b00, rs, rt\}] 100-rs-rt-rd
Store DM[\{2'b00, rs, rt\}] = rd 101-rs-rt-rd
Branch on equal If (rs == rt) pc = pc + 1 + rd
else pc = pc + 1		 110-rs-rt-rd
Jump Next instruction address
pc = pc + \{rs, rt, rd\}		 111-rs-rt-rd

In load, store, branch, and jump instructions, the registers marked in red (rs, rt, rd) represent their indices rather than the values stored within them; consequently, there are no dependency issues.

BRANCH and JUMP update only the architectural PC variable in PATTERN.v. They do not redirect which of the eight instructions will be executed.

➤ Execution Latency

For every test case, the latency of each instruction is independently generated within the following legal range:

Instruction Execution Latency (cycles)
ADD 1 - 5

MUL 20 - 40
DIV 30 - 50
LOAD 6 - 10
STORE 6 - 10
Instruction Execution Latency (cycles)
BRANCH 2 - 4
JUMP 1

PATTERN.v guarantees that every latency value is legal for its corresponding opcode. Within the same test pattern, all instructions with the same opcode share the same execution latency. The latency assigned to each opcode may vary between different test patterns. Since identical instruction encodings may appear at different positions in the input sequence, the output order must be represented using the original instruction indices.

➤ Register Dependency

For any pair of instructions I_i and I_j in the original input sequence, where i < j, the original order I_i \rightarrow I_j must be preserved if at least one of the following dependencies exists:

Type Name Detection Condition Meaning
RAW Read After Write WriteSet(I_i) intersects ReadSet(I_j) I_j needs a value produced by I_i
WAR Write After Read ReadSet(I_i) intersects WriteSet(I_j) I_i must read the old value before I_j overwrites it
WAW Write After Write WriteSet(I_i) intersects WriteSet(I_j) The final write order must remain unchanged

For every dependency I_i \rightarrow I_j: start\_cycle[I_j] \geq finish\_cycle[I_i]

➤ ReadSet and WriteSet

Instruction ReadSet WriteSet
ADD / SUB / MUL / DIV {rs, rt} {rd}
LOAD None {rd}
STORE {rd} None
BRANCH {rs, rt} None
JUMP None None

For STORE, rd is the source data register, not a destination register. For BRANCH, the lowest 3-bit field is an immediate offset. For JUMP, the lower 9 bits are an immediate value; therefore, JUMP does not read or write any register.

➤ Memory Dependency Assumption

No memory dependency occurs in this lab. PATTERN.v guarantees that reordering LOAD and STORE instructions does not change any load result or final memory value. The generated test cases ensure that memory operations access non-conflicting addresses.

Register dependencies used to calculate a memory address or store data are still considered. For example, if an ADD produces the address register used by a later LOAD, a RAW dependency exists between the two instructions.

➤ Dependency-Graph Constraint

For every test pattern, one of the following structures is guaranteed:

  1. 1.No RAW, WAR, or WAW dependency exists among the eight instructions.
  2. 2.Exactly one dependency chain of length 2 to 8 exists, while all remaining instructions are completely independent.
  3. 3.Exactly two vertex-disjoint dependency chains exist, and the two chains together contain all eight instructions.

Instructions in the same dependency chain must preserve their dependency order. No dependency edge exists between different chains or between a chain and an independent instruction. Multi-cycle instructions may appear at any position in a dependency chain and may have both incoming and outgoing dependencies.

➤ Scheduling Model

Single issue:

at most one instruction can begin execution in each cycle.

Overlapped execution:

previously issued independent instructions may execute concurrently.

No structural hazard:

functional units are assumed to be available whenever an instruction is ready. Two instructions of the same type may overlap in execution.

Strict output order: Inst_order_O specifies the exact issue order. If the next instruction in the output order is not ready, the issue stage must stall and cannot skip to a later instruction.

➤ Cycle Calculation

The first instruction may start at cycle 0. If an instruction starts at cycle S and has latency L, it executes during [S, S + L) and completes at cycle S + L.

Flowchart for cycle calculation

A dependent instruction may start exactly at the finish cycle of its predecessor.

Because the longest possible serial chain is eight 50-cycle instructions, a 9-bit

Ex_cycle is sufficient to represent the maximum value of 400 cycles.

Multiple optimal answers are allowed. No index-based tie-breaking rule is required.

➤ Legal but Non-Optimal Order

Order A = I0, I4, I7, I1, I2, I3, I6, I5      Ex_cycle = 74

Order A preserves the chain order I0 -> I4 -> I7. However, I4 is selected immediately after I0 and cannot begin until I0 finishes at cycle 30. Because the output

order is strict, the independent DIV instruction I1 cannot be issued during this waiting interval. I1 therefore starts at cycle 34 and becomes the last completing instruction at cycle 74.

➤ Optimal Order

Order B = I0, I1, I2, I3, I6, I5, I4, I7      Ex_cycle = 41

Order B issues the independent instructions while I0 is executing. I4 starts as soon as I0 completes, and I7 starts as soon as I4 completes. The result cannot be less than 41 cycles: I0 and I1 cannot both start at cycle 0. Starting either one first forces the other long path to complete no earlier than cycle 41.

Optimal order B: I0, I1, I2, I3, I6, I5, I4, I7 (41 cycles)
