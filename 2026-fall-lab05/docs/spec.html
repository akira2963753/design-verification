    1. Overview

    輸入一張 128 x 128、8-bit 灰階影像，輸出壓縮後的 raw entropy bytes。輸出不含 JPEG header / marker，也沒有 0xFF 後補 0x00 的 byte stuffing。

    每個 block 都要依序經過以下處理：

    1. 從 raster 順序的輸入中取出 8x8 block，依 block 0 → 255 的順序處理。
    2. 每個 pixel 減 128。
    3. 做整數 2-D DCT，累加完成後做 round_s(·, 18)，得到 D(u,v)。
    4. 用 shift matrix 量化：Q(u,v) = round_s(D(u,v), S(u,v))。
    5. 依 zigzag 順序排成 Z[0..63]，再做 DC 差分、AC run-length、Huffman 編碼，最後打包成 byte 輸出。

    3. Input Order & Block Organization

    3.1 Raster input

    pixel 依 raster 順序輸入：同一列中 x 從 0 增加到 127，接著 y 加 1。第 k 個 input 的座標為 k = 128y + x。

    3.2 Block 切分

    影像切成 16 x 16 = 256 個不重疊的 8x8 block，block 也依 raster 順序編號，從左上的 block 0 到右下的 block 255。

    4.1 定義

    4.2 對 DCT 係數的影響

    減 128 等於每個 pixel 加上同一個常數，它對 row transform 的貢獻為 −128 · Σx C(u,x)。C 的 u ≥ 1 各列總和為 0 (Table 5)，所以：

    • 63 個 AC 係數完全不受影響。
    • 只有 D(0,0) 平移固定量：有 shift 的 D(0,0) = 沒有 shift 的 D(0,0) − 1024 (= 128 × 8)。

    4.3 目的

    • 數值以 0 為中心：DC 範圍從 0 ~ 2040 變成 ±1024，中間灰階的 block 的 DC 接近 0，後續 entropy coding 的 SIZE 較小。
    • 乘法運算元少 1 bit：C 為 signed，輸入若是 0 ~ 255 需用 9-bit signed 表示；shift 後剛好是 8-bit signed。
    • 與標準 JPEG 一致：標準 JPEG 的 DCT 輸入即定義為以 0 為中心的 signed 值。

    5. Integer 2-D DCT

    5.1 意義

    DCT 把 8x8 block 從空間域轉成 64 個頻率係數 D(u,v)。u 是水平頻率，v 是垂直頻率。D(0,0) 稱為 DC，代表 block 的平均亮度；其餘 63 個稱為 AC，代表亮度的變化。自然影像的高頻 AC 通常很小，量化後多半變成 0，這是後面能壓縮的原因。

    5.2 Integer cosine matrix C

    C 是標準 DCT 的 cosine 值乘上 28 後取整數的 8x8 常數表，所以整個運算都是整數。

    Table 5. Integer cosine coefficient matrix C[freq][pos]

    索引：C 只有一張表，第 1 個參數是頻率 (列)，第 2 個參數是位置 (欄)。spec 表頭寫 C(u,x) 只是借用第一次出現時的變數名稱；column transform 的 C(v,y) 查的是同一張表。

    使用處寫法第 1 參數 (列)第 2 參數 (欄)

    結構：

    • 64 個元素只有 7 種絕對值：181、251、237、213、142、98、50。
    • 偶數列 (u = 0, 2, 4, 6) 左右對稱：C(u,x) = C(u,7−x)。
    • 奇數列 (u = 1, 3, 5, 7) 左右反對稱：C(u,x) = −C(u,7−x)。
    • u ≥ 1 的每一列總和為 0 (見 4.2)。

    5.3 計算

    R(u,y) = Σx=0..7 P'(x,y) · C(u,x)       row transform
A(u,v) = Σy=0..7 R(u,y)  · C(v,y)       column transform
D(u,v) = round_s(A(u,v), 18)

    為什麼除以 218：乘了兩次 C，放大 28 x 28 = 216；標準 2-D DCT 本身還有 1/4 = 2−2 的係數，合計 218。

    R 和 A 在累加過程中不可 round 或截斷，只能在 A(u,v) 算完之後 round 一次。

    5.4 Symmetric signed rounding

    round_s(a, n) =   (|a| + 2^(n−1)) >> n        , a ≥ 0
                −((|a| + 2^(n−1)) >> n)       , a < 0

    先取絕對值、加 2n−1、右移 n 位，再把正負號補回去。剛好 .5 時往遠離 0 的方向進位，正負兩邊對稱。

    為什麼要加 2n−1：右移 n 位等於無條件捨去小數，2n−1 代表 0.5。先加 0.5，小數 ≥ .5 時會先進位到整數部分，捨去小數後留下的就是四捨五入的結果；小數 < .5 時不會進位，直接捨去。

    3.4 + 0.5 = 3.9  → 捨去小數 → 3
3.5 + 0.5 = 4.0  → 捨去小數 → 4
3.7 + 0.5 = 4.2  → 捨去小數 → 4

A = 917504 (A / 2^18 = 3.5)
  A >> 18             = 3     先右移，0.5 已被捨去
  (A + 2^17) >> 18    = 4     round_s 的結果

    以 bit 來看，右移捨去的是最低 n 個 bit (小數部分)，其中 bit n−1 代表 0.5。因此加 2n−1 後是否進位只取決於 |a|[n−1]，下式與 round_s 的絕對值部分等價：

    (|a| + 2^(n−1)) >> n  ==  (|a| >> n) + |a|[n−1]
    OperationCalculationResult
    round_s(25, 3)(25 + 4) >> 3+3
    round_s(−25, 3)−((25 + 4) >> 3)−3
    round_s(28, 3)(28 + 4) >> 3+4
    round_s(−28, 3)−((28 + 4) >> 3)−4
    round_s(−1024, 4)−((1024 + 8) >> 4)−64

    不可直接對二補數加 bias 再做算術右移：(−28 + 4) >>> 3 = −3，正確答案是 −4。

    6. Quantization

    Q(u,v) = round_s(D(u,v), S(u,v))

    每個頻率位置用不同的 power-of-two 除數量化。shift 值 S(u,v) 範圍為 3 ~ 7：低頻位置的 S 較小，保留較多精度；高頻位置的 S 較大，較容易變成 0。S 由 00_TESTBED/src/shift_table.txt 提供，每行一組 U V S。

    DCT 與量化是兩次獨立的 rounding，不可合併成 round_s(A(u,v), 18 + S(u,v))。

    8. Entropy Coding

    8.1 這一步在做什麼

    到 zigzag 為止，每個 block 已經變成 64 個整數 Z[0..63]。Entropy coding 要把這 64 個整數寫成一串 0 和 1，而且越短越好。過程中數值不會改變，解碼端可以從這串 bit 完整還原出 Z。

    以 9.4 的 block 為例 (Fig 8 ①)：最直接的寫法是每個數字固定用 12 bit，64 × 12 = 768 bit。但這 64 個數字只有 3 個不是 0，大部分的 bit 都浪費在寫 0。Entropy coding 用下面 4 個想法，把它縮短到 41 bit：

    1. 0 不要一個一個寫：改成「跳過幾個 0，然後是某個數」。例如 0, 0, +3 寫成「跳過 2 個 0，然後 +3」。後面全部是 0 時，用一個「結束」記號 (EOB) 代表。詳見 8.6。
    2. 小的數字用少一點 bit：先說「這個數有幾個 bit」(SIZE)，再寫出那幾個 bit (amplitude)。+3 只需要 2 bit，不用寫滿 12 bit。詳見 8.4。
    3. 常出現的說明用短碼：「跳過幾個 0、數值有幾個 bit」這樣的說明稱為 symbol。常出現的 symbol 用短碼，少出現的用長碼，這就是 Huffman coding。詳見 8.2。
    4. DC 只記差多少：相鄰 block 的平均亮度通常很接近，所以 Z[0] 不直接寫，只寫它跟前一個 block 的 Z[0] 差多少。−15 跟 −20 只差 +5。詳見 8.5。

    每個 block 產生的 bit 依 block 0 → 255 的順序接在一起，最後切成 byte 輸出 (Section 9)。因為 DC 的差值要用到前一個 block，entropy coding 一定要照 block 的順序做。

    8.2 Huffman Coding 基礎

    概念：Huffman coding 跟摩斯電碼的想法一樣。英文裡最常用的字母 E 只用一個點 ·，很少用的 Q 則用 4 個符號 − − · −。常用的給短碼、少用的給長碼，平均下來整段訊息就變短了。

    在本題中，被編碼的對象是 8.3 介紹的 symbol，例如「跳過 2 個 0，數值有 2 個 bit」。每一種 symbol 都對應一個固定的碼，寫在 TA 提供的表裡。這張表是 JPEG 標準定好的，不需要自己建，只要查表。

    為什麼不需要分隔符號：每個碼的長度不同，bit 之間又沒有分隔，解碼端要怎麼知道一個碼在哪裡結束？這是因為表裡的碼有 prefix-free 的特性：任何一個碼都不會是另一個碼的開頭。解碼端一個 bit 一個 bit 往下讀，只要讀到的 bit 剛好對上表中的某個碼，就一定是它，不會有第二種可能。

    編碼時要做的事：

    1. 決定這次要輸出哪一個 symbol (8.3)。
    2. 查表，得到這個 symbol 的碼 (CODE_BITS) 與碼長 (LENGTH)。表格內容見 8.7。
    3. 從 MSB 開始，輸出剛好 LENGTH 個 bit。

    8.4 SIZE 與 Amplitude

    對任一 signed 值 a：

    • SIZE = |a| 的 bit 數。a = 0 時 SIZE = 0，沒有 amplitude field。

    • a < 0：amplitude 為 (2SIZE − 1) + a，等於 |a| 逐位元反相 (ones' complement)，不是二補數。

    8.5 DC Differential

    每個 block 的 DC 係數 Z[0] 不直接編碼，而是編碼它與前一個 block 的 DC 的差值 delta_dc。相鄰 block 的平均亮度通常接近，差值較小，需要的 bit 也較少。DC 的輸出由兩個 field 組成：先輸出 Huffman code 說明數值有幾個 bit (SIZE)，再輸出 SIZE 個 bit 的數值本身 (amplitude)。

    步驟：對每個 block 依 block 0 → 255 的順序執行

    1. 算差值：delta_dc = Z[0] − previous_dc
    2. 更新 predictor：previous_dc = Z[0]，給下一個 block 使用
    3. 算 SIZE：SIZE = |delta_dc| 的 bit 數 (Table 13)；delta_dc = 0 時 SIZE = 0
    4. 輸出 Huffman code：以 SIZE 為位址查 DC table，輸出 DC_LUT[SIZE] (Table 17)
    5. 輸出 amplitude：輸出 delta_dc 的 SIZE 個 amplitude bit (8.4)；SIZE = 0 時不輸出
    previous_dc = 0                          // 每張圖的 block 0 之前

    previous_dc = Z_b[0]

    emit_huffman(DC_LUT[s])
    emit_amplitude(delta_dc, s)

    8.6 AC Run-Length

    Z[1..63] 由前往後掃描，用計數器 run 記錄目前累積了幾個 0。0 不直接輸出；遇到非零係數時，把「前面 0 的個數 (RUN)」與「這個係數的 SIZE」合成一個 symbol 查 AC table，再輸出係數的 amplitude。結尾剩下的 0 用一個 EOB 表示。

    步驟：

    1. 初始化：run = 0，從 k = 1 開始掃描。
    2. Z[k] = 0：run = run + 1，不輸出，繼續下一個 k。
    3. Z[k] ≠ 0：
      1. 若 run ≥ 16：輸出 ZRL (AC_LUT[8'hF0])，run = run − 16，重複直到 run < 16。
      2. SIZE = |Z[k]| 的 bit 數，輸出 AC_LUT[(run << 4) | SIZE]。
      3. 輸出 Z[k] 的 SIZE 個 amplitude bit (8.4)。
      4. run = 0。
    4. 掃完 k = 63 後：若 run > 0，輸出一個 EOB (AC_LUT[8'h00])；若 run = 0 (Z[63] 非零)，不輸出 EOB。
    run = 0
for k = 1 .. 63:
    if Z[k] == 0: run = run + 1; continue
    while run >= 16:
        emit_huffman(AC_LUT[8'hF0])      // ZRL
        run = run − 16
    s = SIZE(Z[k])
    emit_huffman(AC_LUT[(run << 4) | s])
    emit_amplitude(Z[k], s)
    run = 0
if run > 0: emit_huffman(AC_LUT[8'h00])  // EOB

    9. Bitstream Packing

    9.1 Field 串接

    • 每個 symbol 先輸出 Huffman code，再緊接 amplitude bit，兩者都是 MSB first。
    • 256 個 block 的所有 field 串成一條連續的 bitstream，field 之間與 block 之間不插入任何分隔或 padding。

    9.2 Byte 切分

    bitstream 每滿 8 bit 形成一個 output byte。最早的 bit 放在 out_data[7]，第 8 個 bit 放在 out_data[0]。輸出為 raw byte：出現 FF 時不補 00。

    bitstream : 110 01011 1010 100 1 ...
bytes     : 11001011 10101001 ...
out_data  : CB       A9       ...

    9.3 End-of-Image Padding

    block 255 編碼完後，輸出所有完整的 byte。若剩下 1 ~ 7 個 bit，在尾端補 1 湊滿 8 bit，輸出最後一個 byte；剛好沒有剩餘 bit 時則直接結束。

    11. Decoder

    Decoder 不屬於本題 DUT 的範圍。它是 encoder 的反向流程：把 byte 串還原成 Z，再一路反算回影像。了解 decoder 有助於理解 bitstream 為什麼不需要分隔符號，也可以把 DUT 的輸出解回 Z，找出第一個出錯的 field。

    Entropy decoding 是 lossless，解出的 Z 與 encoder 的 Z 完全相同；量化時被捨去的小數無法找回，所以重建出的影像與原圖不完全相同 (lossy)。

    11.2 Entropy Decoding

    bitstream 從頭開始逐 bit 讀取，依 block 0 → 255 的順序解碼。每個 block 先解 DC，再解 AC：

    1. DC：逐 bit 讀取，直到讀到的 bit 對上 DC table 的某個碼，得到 SIZE；再讀 SIZE 個 bit 還原 delta_dc。Z[0] = previous_dc + delta_dc，接著 previous_dc = Z[0]。
    2. AC：從 k = 1 開始，逐 bit 讀取直到對上 AC table 的某個碼，依 symbol 處理：
      • EOB：Z[k..63] 全部為 0，此 block 結束。
      • ZRL：跳過 16 個 0，k = k + 16。
      • (RUN, SIZE)：跳過 RUN 個 0 (k = k + RUN)，再讀 SIZE 個 bit 還原成 Z[k]，k = k + 1。
      k 到達 64 時 (Z[63] 非零、沒有 EOB) 也結束此 block。
    3. 256 個 block 解完後，剩下的 bit 為 end-of-image padding 的 1，直接忽略。

    Amplitude 還原：讀到的 SIZE 個 bit 中，最高位為 1 代表正數，數值即為該二進位；最高位為 0 代表負數，數值為 value − (2SIZE − 1)，也就是逐位元反相後加上負號。

    31011+5

    previous_dc = 0
for b = 0 .. 255:
    Z = {0, ..., 0}
    s = read_huffman(DC_LUT)                 // 得到 SIZE
    previous_dc = previous_dc + read_amplitude(s)
    Z[0] = previous_dc
    k = 1
    while k < 64:
        sym = read_huffman(AC_LUT)
        if sym == 8'h00: break               // EOB
        if sym == 8'hF0: k = k + 16; continue // ZRL
        k = k + (sym >> 4)                   // RUN
        Z[k] = read_amplitude(sym & 4'hF)   // SIZE
        k = k + 1

    11.3 影像重建

    每個 block 解出 Z[0..63] 後，依下列步驟還原成 64 個 pixel：

    1. Inverse zigzag：Q(ZZ_U[k], ZZ_V[k]) = Z[k]，把一維序列放回 8x8。
    2. Dequantization：D'(u,v) = Q(u,v) × 2S(u,v)。量化時被捨去的部分無法找回，D' 只是 D 的近似值。
    3. 2-D IDCT：使用同一個 C 矩陣與同樣的 218 縮放，只是改成對 (u, v) 加總： 
      P'(x,y) = round_s( Σu Σv C(u,x) · C(v,y) · D'(u,v), 18 )
      DCT 是正交轉換，反轉換就是轉置，所以 C 矩陣可以直接共用。實作上同樣可以拆成先對 v、再對 u 的兩次 1-D 運算。
    4. Inverse level shift：P = P' + 128，超出 0 ~ 255 的值限制在 0 或 255。
    5. 放回影像：block (bx, by) 的 (x, y) 寫到 P(8·bx + x, 8·by + y)。
